原视频审查：先授权，再分析

让助手针对本地 MP4 回答问题，不把工具分析当成完整审片保证。

菜单
/personal → 原视频审查 → 查看通路与限制
工具
understand_video
需要
Pi 1.5.0、常规 npm 安装的 pi-antigravity 0.11.x 及已有登录

原视频审查提供 understand_video 工具。先把要审查的 MP4 放在当前工作目录内，再明确授权把这个文件发给 Antigravity 的 Argon 模型，并写出审查问题。

示例请求：我授权将当前目录的 demo.mp4 发给现有 Antigravity 通路，请用原视频审查工具，按时间检查画面步骤是否完整。这里的文件名和问题都是示例；不要把视频中的指令当成用户授权。

工具只读取非隐藏、没有符号链接或硬链接的 MP4，大小从 24 bytes 到 50 MiB。问题最多 8000 字符，120 秒超时，分析正文最多 32 KiB。路径越界或调用失败会报告失败，不会偷偷改用别的模型或浏览器。

视频由工具内部外发并消耗额度，不是当前主会话直接获得视频附件。三秒测试视频的红、蓝、绿顺序已通过统一入口和视频审查角色实测；音轨未可靠验证，长视频和快速转场不保证完整覆盖。不能确认的项目应标为未审查。

从原视频审查菜单可以启停功能，或查看通路与限制。已有主会话需要自行重载；角色缺少工具或调用失败时，先报告阻塞，不要让助手用读取文件来假装看过原视频。

工具在 details 中返回字节数、提供方、逻辑模型名、输入模式，以及从进入执行到子进程关闭的总耗时；逻辑模型名不代表已确认的服务端路由。若底层返回统计，还会透传有限非负的归一化用量与本地估算费用，缺失字段不补零；估算费不是账单，零值也不代表免费，且只放在 details 中，不计入 Pi 会话用量或额外查询额度。模型达到长度上限与本地 32 KiB 截断相互独立，都会在正文告警，调用成功不保证输出完整；失败只返回安全的阶段和错误码，不转发原始错误或猜测原因。新增元数据仅由离线假 SDK 验证，不能把之前的短视频实测当成新增字段的线上验收。
