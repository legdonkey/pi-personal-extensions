原视频审查：隔离调用，不改变主会话

把原视频交给工具内部的模型调用，并保留输入、权限和验证边界。

工具
understand_video
管理路径
/personal → 原视频审查 → 查看通路与限制
实测环境
Pi 1.5.0、pi-antigravity 0.11.0，常规 npm 安装位置

原视频审查将用户明确授权的本地 MP4 按原始视频格式发送给 Antigravity 的 Argon 模型，以 medium 思考强度分析。这是工具内部调用，不是主会话直接获得视频附件。

父进程和独立 worker 分别检查文件，并比对 SHA-256 摘要。worker 只加载必要的提供方，自行通过 SDK 获取现有 OAuth，按正常动态路由调用 Argon；仅在子进程内注入视频数据，主宿主的 fetch 不变。

只允许当前工作目录内非隐藏、无符号链接或硬链接的 MP4，大小从 24 bytes 到 50 MiB；问题最多 8000 字符，分析正文最多 32 KiB。取消或满 120 秒即终止隔离进程，等待进程关闭后返回；失败不切换提供方、模型或浏览器。

视频会外发并消耗额度，当前不汇入主会话用量统计。统一入口和 video-reviewer 的真实工具调用，均正确识别三秒测试视频的红、蓝、绿顺序；这只验证短视频视觉通路，音轨未可靠验证，长视频和快速转场不保证完整覆盖。

全局注册不等于角色获权。video-reviewer 需要显式允许这个工具。当前后台子代理已实测可继承父会话扩展，无需额外指定扩展路径；其余只读权限、全新上下文和模型覆盖保持不变。已打开的主会话需自行重载，再从原视频审查菜单查看通路与限制。

工具在 details 中返回字节数、提供方、逻辑模型名、输入模式，以及从进入执行到子进程关闭的总耗时；逻辑模型名不代表已确认的服务端路由。若底层返回统计，还会透传有限非负的归一化用量与本地估算费用，缺失字段不补零；估算费不是账单，零值也不代表免费，且只放在 details 中，不计入 Pi 会话用量或额外查询额度。模型达到长度上限与本地 32 KiB 截断相互独立，都会在正文告警，调用成功不保证输出完整；失败只返回安全的阶段和错误码，不转发原始错误或猜测原因。新增元数据仅由离线假 SDK 验证，不能把之前的短视频实测当成新增字段的线上验收。
