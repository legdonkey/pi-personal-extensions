原位思考强度：每条消息自动选档位

用 GPT-6 Codex、Anthropic 协议分支的四个指定 Claude 模型或 Antigravity 分支的两个指定 Claude 模型时，按每条新消息的难度自动选档位，你不用手动切换。不用这些模型可以跳过本章。

功能
原位思考强度
入口
/personal → 原位思考强度
配置文件
agent 目录下的 inline-effort.json（默认 ~/.pi/agent/）；升级后原有设置自动保留

「原位思考强度」能帮你什么

思考强度分五个档位。「原位思考强度」给每条新消息在 low 到 max 之间自动选一档，你不用手动切换。 它只调档位，不换主模型。 扩展按主模型用两套规则选档。Opus 5.5、Sonnet 5.5、Fable 5.2、GPT-6 Astra 和 GPT-6.1 Sol 各用一套按官方指南整理的规则；Opus 5 和其他 GPT-6 Codex 模型用通用规则：low 到 xhigh 对应直接操作、局部判断、多约束综合与耦合推理四档常规工作，max 是例外攻坚档。 通用规则下，近期对话只补全同一任务的信息，不继承旧难度。示例：修改位置和方式明确的字号调整可用 low，改做图示设计可用 high；按成熟口径查数画图可用 medium，排查混杂原因可用 xhigh。示例不是线上分类保证。 通用规则不因专业主题、成片精美、代理多或反复报错自动提档；只有无法识别任务要求时才以 high 保守兜底。思考强度不替代模型专长、授权和实测。两套规则下，分类器都只读有限文本，看不到图片和工具结果，同轮工具续调不重新分类，历史决策不变。 三个 Claude 模型的规则来自 Claude Code 的 auto-effort mod，已有上一轮回复时会参考上一轮实际生效档位。规则举例：你指出上一轮跳过文件、没跑测试或半途放弃时，至少比上一轮高一档；用 Fable 5.2 时，上一轮在 low 或 medium 提前停下、你要求继续做完，给 high。举例不是线上分类保证。 GPT-6 Astra 和 GPT-6.1 Sol 的规则按 OpenAI 和 Codex 的官方文档整理，默认档是 low，已有上一轮回复时同样参考上一轮实际生效档位。规则举例：Astra 的档位刻度偏高，绝大多数任务不需要 max；Sol 低档事实核实已够用，冲突证据权衡与联动精修交付用 xhigh。

想让它生效

需要用支持的模型、开启 thinking，并配好 OpenRouter 认证。使用 Codex 还要登录 openai-codex。使用 Antigravity 还要先安装并启用 pi-antigravity。主模型的接口和模型能力也有要求，完整条件写在本节的「适用条件」列表里。

  1. 用支持的模型启动 Pi，thinking 设为 medium。下面用 GPT-6 Codex 举例。
  2. 输入 /personal，选原位思考强度，再选「查看分类模型与状态」。看到「适用」，说明主模型和 thinking 符合条件。
  3. 在同一个菜单里选「测试分类模型可用性」，确认分类器能用。
  4. 发一条消息，看 🧠 段的档位。切换警告只表示首选报错，Jev 回退成功后会显示实际档位；未获合格结果才沿用当前档位。Codex 出现「未调整」，表示这次没有调整档位，按基线发出。

三个分支的写入方式不同。Codex 在当前用户消息前插入 configuration_update。Anthropic 协议分支只修改 Pi 已生成的末尾空 system 消息中的 output_config.effort，不改顶层配置、历史消息或 thinking block。 Antigravity 是独立分支。扩展临时包装插件原生 streamSimple，只改匹配主请求的 options.reasoning，由插件按 runtime ID 路由。max 和 xhigh 夹到 high，不改会话 thinking 或历史上下文。 Fable 5.2 只在 Anthropic 协议分支生效。它依据 Pi 的模型目录接入逐消息档位，真实请求的缓存命中还没验证。

状态栏的 🧠 段怎么读

🧠 段从左到右是：实际档位、基线和分类器。基线是 Pi 当前的 thinking 设置。 Pi 自带的 thinking 显示只是基线，实际档位看 🧠 段。 同一会话两次检测到缓存重建后，🧠 段改为显示「自动调整暂停」和恢复的菜单路径，见本章「缓存重建后暂停」一节。

想看现在的状态

在 /personal 的原位思考强度菜单里选「查看分类模型与状态」，看是否适用、之后用哪个分类器、失败回退策略、上一条消息选到的档位。

想换分类器

  1. 输入 /personal，选原位思考强度。
  2. 选「选择分类模型」。
  3. 用 ↑ ↓ 键选 Jev、d1-ultra、Mammoth 27B 或 Decider v1.2。
  4. 按 Enter 键保存；按 Esc 键放弃。两种操作都会返回二级菜单。

新分类器对所有会话生效。如果 Pi 正在回复，先等它回复完，再切换。

分类失败怎么办

首选非 Jev 模型请求超时或服务出错时，警告会说明原因并提示正在切换到 Jev。Jev 成功后，提示实际档位，状态栏显示如「Jev（d1-ultra 回退）」。 如果返回结果无效或概率未达 0.5，不触发回退，直接保持当前思考强度不变：结果无效发一次警告，概率低于 0.5 不发警告。可在 /personal 的原位思考强度菜单里选「测试分类模型可用性」检查。 自动回退只影响本次，不改全局选择，下一条新消息仍先尝试首选模型。直接选择 Jev 时不反向回退。用户取消时停止分类，不回退，也不写决策。 分类在你提交消息时就开始。发请求时如果还没完成，最多再等 5 秒；超过就沿用当前档位，丢弃迟到的结果，同一会话只在第一次提醒。

缓存重建后暂停

调整过档位后，如果主模型这次的缓存读取比上一次少，扩展会提示「检测到缓存重建」，并写明两次读取量和可能原因。只是缓存写入变大不算。每轮最多计一次。 同一会话累计两次后，扩展暂停自动调整：之后的消息沿用当前档位，不再调用分类器，🧠 段显示暂停原因和恢复路径。 想恢复，在 /personal 的原位思考强度菜单里选「恢复自动调整」，计数也会清零。切换主模型不会解除暂停，开始新会话会清零。 缓存过期、压缩、树导航和切换模型都会让缓存正常失效，这些情况不做判断。这仍只是提醒信号：服务端提前清除缓存，或其他扩展改了提示词，也可能触发。

想知道分类器选档准不准

在 /personal 的原位思考强度菜单里选「运行判档测评」。确认会消耗 OpenRouter 额度后开始，按 Esc 键随时取消；Pi 正在回复时不能运行。 测评用 75 个用例，分别按 Opus 5.5、Sonnet 5.5 和 Fable 5.2 的规则判一遍，共 225 次分类，结果显示命中率、偏低、偏高、无效数和中位耗时。它只调用分类器，不调用主模型。 明细保存在 agent 目录的 inline-effort-bench 文件夹，不含用例原文。用例来自开源项目 effortless，使用 MIT 许可。 测评期间，首选分类器失败也不会逐条弹出切换警告；回退到 Jev 的次数和原因分布写在结束时的汇总里。 2026 年 11 月 14 日用 Jev 实测一次：按 Opus 5.5 的规则命中 74 个，Sonnet 5.5 命中 64 个，Fable 5.2 命中 71 个，225 次调用约 0.016 美元。

要注意什么：额度和隐私

你提交消息时，扩展就在后台分类，发请求时最多再等 5 秒。分类、回退和判档测评都消耗 OpenRouter 额度，四个分类模型均按输入计费。 「原位思考强度」把当前消息和之前最多 6 条对话消息的文本发给分类器，可能含业务信息。工具输出、思考内容和图片不发送。
