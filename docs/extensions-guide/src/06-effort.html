原位思考强度：按消息选档位

按每条新用户消息调整 GPT-6 系列的思考档位。顶层参数保持基线，档位写进 input 里这条消息的位置。

功能 ID
jev-inline-effort
入口
/personal → 原位思考强度（Jev / d1-ultra）
配置
默认 ~/.pi/agent/jev-inline-effort.json，目录跟随 PI_CODING_AGENT_DIR
分类器
Jev（默认）· d1-ultra

什么时候分类

不同的消息需要的思考强度不同。这项功能给每条新用户消息自动选一个档位，结果叫决策。档位是思考强度的取值，分类器从 low、medium、high、xhigh、max 五档里选。 接口是 openai-codex-responses，模型属于 GPT-6 系列，thinking 不是 off，三个条件都满足叫适用。不适用就不分类。 空白输入不调用分类器，沿用当前强度。当前强度是当前分支最近一次决策；没有决策就用基线，也就是 Pi 的 thinking 设置。 非空才调用分类器，最多等 15 秒。

分类结果怎么用

分类正常完成、档位有效，且概率是 0.5 到 1 之间的有限数，这叫结果合格。结果合格，扩展就采用这个档位。 超时、出错或响应无法解析时，扩展沿用当前强度并警告。结果不合格时也沿用，但不警告。 两种情况都写入决策；用户取消时不写。 多条新消息只分类一次，结果写给每一条。

为什么不改顶层参数

Pi 每次请求前，都按当前上下文构造完整的 input 列表。基线写在请求顶层的 reasoning.effort 字段。 新请求开头里和上一次请求相同的部分，叫缓存前缀。服务端复用缓存前缀的机制叫 prompt cache。README 的设计目标是保留缓存前缀，让 prompt cache 生效。 如果直接改顶层，请求 2 从顶层字段起就和请求 1 不同。Pi 的 WebSocket 增量续传也要求 input 和 previous_response_id 以外的字段不变，否则发送完整 input。

插入 configuration_update

扩展让顶层保持基线，在当前用户消息前插入一个 configuration_update 项，只写新档位。档位写在 input 里这条消息的位置上，这就是「原位」。 决策按消息时间戳存在会话里。模型、基线和已有上下文不变时，下一次请求在同样位置插入同样的项，开头逐项不变。 档位和当前强度相同时，扩展不插入。档位回到基线时，扩展也要插入一项，抵消之前那一项。

决策跟随会话分支

决策是会话里的自定义条目，不发给模型。扩展只读当前分支路径上的决策，所以恢复会话、fork 或树导航后，旧消息保持原档位，不重新分类。 从 A1 另开分支 b 时，扩展仍继承共同祖先 U1 的决策，但读不到分叉后 U2 的决策。U3 是新消息，重新分类。 压缩后，压缩摘要承接被压缩部分的最后一次决策，强度不回落到基线。

状态栏

状态栏的 🧠 段显示当前强度、基线和最近一次决策的分类器，例如 🧠 xhigh · 基线 medium · Jev。当前强度等于基线时，只显示一个档位。 插入前，扩展核对 input 里 role 为 user 的项数。项数和本次上下文不一致时，扩展不插入，状态栏显示「未调整」。

在 /personal 里管理

在 /personal 里选原位思考强度，再选「查看分类模型与状态」。它显示三项：是否适用、后续用哪个分类器、当前分支最近一次决策。 「选择分类模型」打开选择器；「使用 Jev 分类模型」和「使用 d1-ultra 分类模型」直接保存。选择存进全局配置，从下一条未分类的消息生效。 「测试分类模型可用性」用固定样例测试分类器，不写决策。Pi 运行 agent 时，选择和测试都不可用。

子代理与代价

子代理要加载本扩展才会分类，基线取子代理自己的 thinking 设置。外部 CLI 代理不经过本扩展。 代价有三项：每条新消息多等一次分类；分类消耗 OpenRouter 的额度；发出的文本可能含业务信息。d1-ultra 是付费模型。
