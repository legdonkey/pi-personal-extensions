# Pi 宿主规则

本包保留上游的设计指令、参考文件和运行资源。
Pi 扩展提供命令入口、引擎工具和自动检测。
宿主行为有差异时，采用本文件中的 Pi 规则。

## 入口与路径

- 用 `/impeccable <命令> <目标>` 执行设计任务。
- 用 `/impeccable` 获取当前项目的操作菜单。
- 用 `/impeccable help` 查看 24 个设计命令。
- 用 `/impeccable pin audit` 创建 `/audit` 快捷命令。
- 用 `/impeccable unpin audit` 移除快捷命令。
- 用 `/skill:impeccable <请求>` 显式加载技能。

`<skill-base-dir>` 表示本文件上一级目录，即包含 `SKILL.md` 的绝对目录。
执行参考文件中的命令时，必须先替换这个占位符。
项目工作目录与技能目录是两个位置。保持工作目录为用户项目。

优先调用 `impeccable` 工具。它接受参数数组，避免路径和引号被 shell 重新解释。
例如：`{"argv":["context","--target","src/pages/index.astro"]}`。
引擎输出中的后续命令同样可以转换为 `argv`。
引擎首次使用时下载正式 Release，执行前校验固定的 SHA-256。

没有该工具时，运行 `node "<skill-base-dir>/scripts/run.mjs" <参数>`。
POSIX 和 Windows 启动器也可用。本包需要 Node.js 22.19 或更新版本。
下载或校验失败时，报告具体错误。不得临时执行未固定版本的 `npx impeccable`。

## 自动检测与项目配置

Pi 在成功的 `edit`、`write` 和 `apply_patch` 后运行上游 `PostToolUse` 检查。
嵌套工具调用也经过该事件。普通 shell 写入不属于直接编辑事件。
用 shell 修改 UI 时，完成后必须手动运行一次 `detect`。

结束前的 `Stop` 检查使用完整规则，保留上游的分层检查、去重和忽略规则。
发现待修复问题后，Pi 最多追加一轮模型工作，避免自动检查无限续调。
检查失败时，报告失败并执行一次手动检测。不得把失败当作通过。

`hooks` 的配置管理和忽略规则仍由上游引擎处理。
`hooks on` 启用共享项目配置；`hooks off` 禁用。
Pi 通过扩展事件执行检查，无需其他宿主的 hook manifest。
本包工具返回的 `PI_AUTOMATIC_DETECTOR` 表示当前扩展已提供自动检查。
此时不执行 `MANUAL_DETECTOR_REQUIRED` 中的重复扫描。

`hooks reset` 会按上游语义删除共享配置和检测缓存。
执行前必须确认用户要求重置这些文件。
其他宿主已安装的 Impeccable 配置也受上游管理命令影响。
不要为了启用 Pi 检查，额外安装 Claude Code、Codex 或 Cursor 的配置。

## 子代理与角色

必须遵循当前 Pi 会话的委派授权规则。
技能加载和普通设计请求本身不授予子代理权限。
用户明确授权委派后，读取 `pi-subagents` 技能或工作流指南。
先检查可执行代理，再用一个异步工作流组织多个子任务。
独立评审使用新上下文；并行写入使用隔离工作区。

本包保留四个上游角色的完整指令：

| 角色 | 指令文件 |
|---|---|
| 素材制作 | `degraded/asset-producer.md` |
| 交付评审 | `degraded/finish-reviewer.md` |
| 设计系统记录 | `degraded/documenter.md` |
| Live 手动编辑落盘 | `degraded/manual-edit-applier.md` |

获准委派时，把角色正文和本次任务传给已验证可执行的代理。
不得猜测 `impeccable-*` 名称已在用户环境注册。
未获授权或没有代理工具时，按上述文件在当前线程执行，并披露评审方式。
执行角色正文时忽略其针对“不支持子代理的宿主”的开头说明。

## 浏览器、图像与交互

有 `ego-browser` 时，先读取该技能，用它打开页面、观察和操作。
只有宿主没有浏览器工具时，才要求用户手动打开 Live 页面。
Live 的服务端、覆盖层、选择器、变体、接受、丢弃与恢复由上游引擎提供。

用 `impeccable` 工具运行 `live-poll`。默认给它 10 分钟长轮询。
工具的超时为 11 分钟，留出引擎返回超时事件的时间。
收到事件后按 `live.md` 处理，回复后立即再次轮询。
不得在未运行轮询时声称正在等待浏览器事件。
停止轮询不会自动撤销变体。按 `live.md` 清理或恢复活动会话。

只有用户明确请求创建或编辑栅格图像时，才调用图像生成工具。
上传本地参考图、费用告知和生成目标路径必须遵循宿主规则。
缺少图像生成权限时，按上游 code-first 流程构建。

自然语言、项目文案和交付说明默认使用用户语言。
中文技术内容遵循当前环境的中文写作规则。
上游英文参考文本用于保留原始设计约束，无需整体翻译。
