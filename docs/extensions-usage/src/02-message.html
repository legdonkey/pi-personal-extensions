消息区：线框和可点的路径

自己的消息带橙色线框，回复里的文件路径点一下就在编辑器里打开。

功能
用户消息橙色线框；文件路径可点击
在哪设置
/personal → 选对应功能

想在长对话里找到自己的消息

你发出的每条消息都带橙色圆角线框，左上角写着 user。在长对话里，你更容易找到自己的消息。 不想要，就在 /personal 里关闭这项功能。

  • 「用户消息橙色线框」没有设置项，也不改消息内容。关闭步骤见第 1 章。
  • 升级 Pi 后，线框可能不再显示。消息本身照常显示，等扩展更新即可。

想直接打开回复里提到的文件

回复里的本地文件路径会变成链接，点击后编辑器打开这个文件。 多数终端要按住修饰键再点击：macOS 上常是 Cmd 键，其他系统常是 Ctrl 键。 路径带行号和列号时，编辑器直接跳到那个位置。

  • 具体按键以终端的设置为准；有的终端直接点击就能打开。
  • 只有真实存在的文件才变成链接。相对路径按会话的工作目录查找。
  • 例如 src/app.ts:12:5 跳到第 12 行第 5 列。
  • 你发的消息里的路径，默认也会变成链接。这一项没有菜单入口。如果不想要：
    1. 打开 agent 目录下的 clickable-paths.json（默认 ~/.pi/agent/）。
    2. 把 userMessages 设为 false，保存。
    3. 输入 /reload。

想换一个编辑器打开

默认用 VS Code 打开。想换编辑器，在 /personal 的「文件路径可点击」里选「打开方式」。 打开方式选 file 时，系统用默认程序打开文件，不跳到具体行。

  1. 输入 /personal，按 Enter 键。
  2. 用 ↑ ↓ 键选「文件路径可点击」，按 Enter 键。
  3. 选「打开方式：cursor」这类菜单项，按 Enter 键。

哪些路径会变成链接

没用反引号包起来的路径叫裸路径。裸路径要带扩展名才会变成链接，比如 README.md。 代码块和思考内容里的路径不变成链接。回复输出完以后，路径才变成链接。

  • 代码块指用 ``` 或 ~~~ 包起来的部分。已经写成链接的文字保持原样。
  • 不想识别裸路径：在「文件路径可点击」的二级菜单里选「不识别裸路径」；恢复选「识别裸路径」。

路径没变成链接怎么办

  1. 在 /personal 的「文件路径可点击」里选「查看路径链接设置」，确认「状态」是「开启」。
  2. 确认文件真实存在，并且路径不在代码块或思考内容里。
  3. 如果路径后面跟着括号里的链接地址，说明终端超链接没有启用。这时检查 Pi 的超链接设置、PI_HYPERLINKS 环境变量和终端本身。

Pi 按这个顺序决定是否启用终端超链接：

  1. Pi 设置 terminal.hyperlinks：true 启用，false 关闭。写在 agent 目录或项目 .pi/ 下的 settings.json。
  2. 环境变量 PI_HYPERLINKS：1 启用，0 关闭，启动 Pi 前设置。
  3. 两者都没设置时自动检测：iTerm2、kitty、Ghostty、WezTerm、Warp、Windows Terminal、Alacritty，以及 VS Code 和 Zed 的内置终端会启用，其他终端不启用。在 tmux 里，要 tmux 转发超链接才启用。
路径变成了链接，但点了没反应
  1. 确认按住了修饰键，具体按键以终端设置为准。
  2. 选「查看路径链接设置」看「编辑器」，确认这个编辑器已经安装。
  3. 选「打开方式：file」，换成系统默认程序打开。已显示的消息不会刷新，旧链接地址可能不变：让 Pi 重新输出一个文件路径，再点新消息里的链接测试。

第 1 步的实际画面

选「查看路径链接设置」后，Pi 列出「状态」「编辑器」「裸路径」「工作目录」四行，最后一行提示在 /personal → 文件路径可点击 里设置。

  • 暂停路径链接：选「暂停路径链接」，从下一条消息开始生效。恢复：选「开启路径链接」。
