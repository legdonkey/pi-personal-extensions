状态栏：额度与配色

「状态栏：额度、会话 ID 与配色」是一项功能、一个开关：往状态栏写额度和会话 ID，也给状态栏换配色。

功能
状态栏：额度、会话 ID 与配色（statusline，源码 extensions/statusline.ts）
菜单路径
/personal → 状态栏：额度、会话 ID 与配色
配置
pi-statusline.json
依赖
配色生效需要另行启用 npm:@narumitw/pi-statusline 包；Antigravity 额度需要另行启用 pi-antigravity

额度：什么时候刷新

想在状态栏看到服务商还剩多少额度，可以开启「状态栏：额度、会话 ID 与配色」。它在状态栏写会话 ID 的末尾 8 位和服务商剩余额度，也提供 11 套配色。 会话开始、树导航、切换模型时，扩展立即刷新额度。会话开始或树导航后，定时器每 5 分钟再刷新一次。 agent 一轮运行结束时，扩展也刷新额度。如果距上次刷新开始少于 30 秒，扩展跳过这次刷新。

  • 会话 ID 只显示末尾 8 位。Pi 默认用 UUIDv7 生成会话 ID，开头是时间戳，相近时间新建的会话开头相同，所以扩展取末尾。
  • 切换模型时，扩展取消还没完成的请求。会话关闭时，扩展停止定时器、取消请求，并清空两项状态。
  • 这一项由旧版的 substatusline 和 statusline-style-picker 合并而来，只有一个开关 statusline。配置里没有新开关时，由两个旧开关推出：两个都明确为 false 才关闭，否则开启。下次保存开关时只写新键。

一次刷新做什么

一次刷新分三步。第一步，扩展读取当前模型所属服务商的凭据。Antigravity 从当前 provider 获取 JSON 凭据，其他服务商调用 pi auth。 第二步，扩展带凭据请求服务商的用量接口。前三个服务商读取凭据和请求接口各有 15 秒超时。Antigravity 使用固定官方 endpoint 回退，总网络超时 15 秒。 第三步，扩展挑出额度窗口或当前模型配额，显示剩余百分比。额度窗口是按时间段统计的限额。openai-codex 显示周额度，zai-coding-cn 显示 5 小时和周额度，kimi-coding 显示 5 小时额度，老套餐附周额度，新套餐附月度额度。antigravity 显示 quota 60% left 这样的当前模型配额。这个配额可能使用共享池，不是独立的 5 小时或周窗口，也不是 token 计数。 请求失败时，其他服务商保留上次成功的值。Antigravity 找不到当前模型配额或查询失败时隐藏旧值。从没成功过时，额度一项为空。

  • 当前模型来自其他服务商时，额度一项为空。Antigravity 额度需要先安装并启用 pi-antigravity。
  • Codex、智谱和 Kimi 的剩余百分比 = 100 − 已用百分比，限制在 0～100，四舍五入。Antigravity 只接受有限数值 remainingFraction，约束到 0～1，再乘 100 并四舍五入；多个同模型变体取最低值。
  • Antigravity 按当前模型精确 ID 匹配，也匹配去掉 -extra-low、-extra-high、-minimal、-medium、-high、-low、-thinking、-tiered 后缀的运行变体。gemini-3.1-pro 还匹配 gemini-pro-agent，gemini-3.5-flash 还匹配 gemini-3-flash-agent。
  • Antigravity 每次刷新重新解析当前账号凭据。账号变化在下一刷新生效，扩展不主动监听账号切换。切换模型会强制查询，不显示旧模型缓存。

换配色

在 /personal 的「状态栏：额度、会话 ID 与配色」里，选择 pi-statusline 自定义配色。需要另外安装并启用 pi-statusline，不改变 Pi 主题。 终端里上下键实时预览，Enter 应用，Esc 取消；RPC 客户端使用普通列表。应用后覆盖自定义配色，并设置紧凑布局和圆角分隔符。

11 套配色怎么分组

每行是一套配色。每套有 6 组颜色，每组是一对前景色和背景色。 状态栏的 13 个字段按表头分成 6 组，同组字段共用一组颜色。 终端宽度小于 68 列时，预览拆成两行。每行都按终端宽度截断。

应用配色时写什么

应用配色时，扩展先读出原来的 pi-statusline.json。 扩展整体替换四个字段：配色预设、配色、密度和分隔符。其他顶层字段保留。 写入方式和第 2 章的启停相同：临时文件加 rename，成功后重载，失败不重载。

  • 文件位置：agent 目录下的 pi-statusline.json，和 pi-statusline 读取的位置相同。agent 目录默认是 ~/.pi/agent/，设置了 PI_CODING_AGENT_DIR 时用这个变量指定的目录。
  • 文件不存在时，扩展从空对象开始写；读取出错或不是合法 JSON 时，算作失败。
