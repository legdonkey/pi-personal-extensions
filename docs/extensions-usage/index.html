装上 pi-personal-extensions 后，Pi 终端里会多出七项功能。这页讲每项功能能帮你什么、怎么开启、怎么用，出问题时先查什么。朗读时，正在读的句子会高亮，图跟着点亮。

上手：安装、设置、关闭功能

七项功能能帮你什么，怎么安装，怎么用 /personal 开启、关闭和设置。

运行要求
Pi ≥ 1.0.1，Node.js ≥ 22.19
管理命令
/personal、/personal switches

这套扩展能帮你什么

这套扩展提供七项功能，默认全部开启。

  • 消息区里，你发的消息带橙色线框；回复里的文件路径可以点击打开。
  • 状态栏显示会话 ID 和服务商的剩余额度。状态栏的配色也能换。
  • 输入框下方显示会话名。一轮指你发出一条消息，到 Pi 回复完。每轮正常结束后，「自动会话命名」在后台起会话名。
  • 用 GPT-6 Codex、Anthropic 协议分支的三个指定 Claude 模型或 Antigravity 分支的两个指定 Claude 模型并开启 thinking 时，「原位思考强度」给每条新消息自动选档位，结果显示在状态栏的 🧠 段。另有接口和模型能力要求，见下方条件列表。
  • 原视频审查在用户授权后，把本地 MP4 交给 Argon 分析；详见原视频审查章节，音轨未可靠验证。

原位思考强度要求 thinking 不是 off。GPT-6 Codex 使用 openai-codex-responses 接口，模型 ID 以 gpt-6 开头。Anthropic 协议分支使用 anthropic-messages 接口，compat.supportsMidConvoEffort === true，模型 ID 精确等于 claude-opus-5、claude-opus-5-5 或 claude-sonnet-5-5。Antigravity 分支要求 provider 为 antigravity、接口为 antigravity-api，模型 ID 精确等于 claude-opus-5-5 或 claude-sonnet-5-5，并先安装和启用 pi-antigravity。

要安装

在仓库根目录依次执行三条命令：安装依赖，可选的检查，再用 pi install 装进 Pi。 新开的 Pi 会话会自动加载；已经打开的会话，输入 /reload。 

# 0. 取得仓库（已有仓库可跳过）
git clone https://github.com/legdonkey/pi-personal-extensions.git
cd pi-personal-extensions
# 1. 安装依赖（走 npmmirror 镜像）
npm install --ignore-scripts \
  --registry=https://registry.npmmirror.com
# 2. 运行检查（可选：确认代码完整）
npm run check
# 3. 装进 Pi
pi install "$(pwd)"

# 卸载：在仓库根目录执行
pi remove "$(pwd)"

更新扩展的方法见第 6 章「想更新扩展」。

想关闭某项功能，或改它的设置

  1. 在 Pi 里输入 /personal，打开统一管理菜单。菜单列出七项功能，并标出已加载或未加载。
  2. 选中一项功能，进入它的二级菜单。
  3. 如果要关闭这项功能，选二级菜单的最后一项「禁用此功能并重载」。Pi 会自动重载。
  4. 按 Esc 键逐级返回，一级菜单才退出。保存设置后仍留在二级菜单；需要重载时退出。
  • Pi 正在回复或压缩时，重载会被拒绝。等它结束再操作，或结束后手动输入 /reload。
  • 七项里有四项在二级菜单里有设置项。例如「自动会话命名」可以选命名模型。
  • 「已加载」只表示功能已加载，不表示它正在工作。例如「自动会话命名」可能在当前会话里暂停。

想一次开启或关闭好几项

  1. 输入 /personal switches，打开「批量功能开关」。
  2. 用 ↑ ↓ 键选一项功能。
  3. 按 空格 键，在开启和关闭之间切换。
  4. 按 Enter 键保存，当前会话自动重载；按 Esc 键放弃。
  • 其他已打开的会话，要各自输入 /reload。
  • Pi 正在回复或压缩时，重载会被拒绝；结束后手动输入 /reload。
  • /personal 有交互界面就能用（Pi 终端界面、RPC 客户端）；「批量功能开关」只在 Pi 终端界面里可用。
  • 关闭一项功能时，这项功能的设置会保留。重新开启后，设置还在。

消息区：线框和可点的路径

自己的消息带橙色线框，回复里的文件路径点一下就在编辑器里打开。

功能
用户消息橙色线框；文件路径可点击
在哪设置
/personal → 选对应功能

想在长对话里找到自己的消息

你发出的每条消息都带橙色圆角线框，左上角写着 user。在长对话里，你更容易找到自己的消息。 不想要，就在 /personal 里关闭这项功能。

  • 「用户消息橙色线框」没有设置项，也不改消息内容。关闭步骤见第 1 章。
  • 升级 Pi 后，线框可能不再显示。消息本身照常显示，等扩展更新即可。

想直接打开回复里提到的文件

回复里的本地文件路径会变成链接，点击后编辑器打开这个文件。 多数终端要按住修饰键再点击：macOS 上常是 Cmd 键，其他系统常是 Ctrl 键。 路径带行号和列号时，编辑器直接跳到那个位置。

  • 具体按键以终端的设置为准；有的终端直接点击就能打开。
  • 只有真实存在的文件才变成链接。相对路径按会话的工作目录查找。
  • 例如 src/app.ts:12:5 跳到第 12 行第 5 列。
  • 你发的消息里的路径，默认也会变成链接。这一项没有菜单入口。如果不想要：
    1. 打开 agent 目录下的 clickable-paths.json（默认 ~/.pi/agent/）。
    2. 把 userMessages 设为 false，保存。
    3. 输入 /reload。

想换一个编辑器打开

默认用 VS Code 打开。想换编辑器，在 /personal 的「文件路径可点击」里选「打开方式」。 打开方式选 file 时，系统用默认程序打开文件，不跳到具体行。

  1. 输入 /personal，按 Enter 键。
  2. 用 ↑ ↓ 键选「文件路径可点击」，按 Enter 键。
  3. 选「打开方式：cursor」这类菜单项，按 Enter 键。

哪些路径会变成链接

没用反引号包起来的路径叫裸路径。裸路径要带扩展名才会变成链接，比如 README.md。 代码块和思考内容里的路径不变成链接。回复输出完以后，路径才变成链接。

  • 代码块指用 ``` 或 ~~~ 包起来的部分。已经写成链接的文字保持原样。
  • 不想识别裸路径：在「文件路径可点击」的二级菜单里选「不识别裸路径」；恢复选「识别裸路径」。

路径没变成链接怎么办

  1. 在 /personal 的「文件路径可点击」里选「查看路径链接设置」，确认「状态」是「开启」。
  2. 确认文件真实存在，并且路径不在代码块或思考内容里。
  3. 如果路径后面跟着括号里的链接地址，说明终端超链接没有启用。这时检查 Pi 的超链接设置、PI_HYPERLINKS 环境变量和终端本身。

Pi 按这个顺序决定是否启用终端超链接：

  1. Pi 设置 terminal.hyperlinks：true 启用，false 关闭。写在 agent 目录或项目 .pi/ 下的 settings.json。
  2. 环境变量 PI_HYPERLINKS：1 启用，0 关闭，启动 Pi 前设置。
  3. 两者都没设置时自动检测：iTerm2、kitty、Ghostty、WezTerm、Warp、Windows Terminal、Alacritty，以及 VS Code 和 Zed 的内置终端会启用，其他终端不启用。在 tmux 里，要 tmux 转发超链接才启用。
路径变成了链接，但点了没反应
  1. 确认按住了修饰键，具体按键以终端设置为准。
  2. 选「查看路径链接设置」看「编辑器」，确认这个编辑器已经安装。
  3. 选「打开方式：file」，换成系统默认程序打开。已显示的消息不会刷新，旧链接地址可能不变：让 Pi 重新输出一个文件路径，再点新消息里的链接测试。

第 1 步的实际画面

选「查看路径链接设置」后，Pi 列出「状态」「编辑器」「裸路径」「工作目录」四行，最后一行提示在 /personal → 文件路径可点击 里设置。

  • 暂停路径链接：选「暂停路径链接」，从下一条消息开始生效。恢复：选「开启路径链接」。

状态栏：看额度，换配色

「状态栏：额度、会话 ID 与配色」在状态栏显示剩余额度和会话 ID，也能给状态栏换配色。

功能
状态栏：额度、会话 ID 与配色（一个开关）
菜单路径
/personal → 状态栏：额度、会话 ID 与配色
前提
换配色需要先装 npm:@narumitw/pi-statusline；Antigravity 额度需要先装 pi-antigravity
配置文件
agent 目录下的 pi-statusline.json（默认 ~/.pi/agent/）

想看懂状态栏上的额度和会话 ID

「状态栏：额度、会话 ID 与配色」在状态栏显示两样东西：当前会话 ID 的末尾 8 位，和当前服务商还剩多少额度。 用 openai-codex 时显示周额度（weekly）；用 zai-coding-cn 时，前面多一段 5 小时额度（5h）。用 kimi-coding 时也显示 5 小时额度，老套餐附周额度，新套餐附月度额度（monthly）。用 antigravity 时显示 quota 60% left 这样的当前模型配额。这个配额可能使用共享池，不是独立的 5 小时或周额度，也不是 token 计数。

  • 额度、会话 ID 和配色是同一项功能，共用一个开关。升级时，旧版的两个开关合成这一个：只有两个旧开关都关闭，才保持关闭；否则开启。

额度一项是空的怎么办

  1. 先看当前模型的服务商。只有 openai-codex、zai-coding-cn、kimi-coding 和 antigravity 显示额度。用其他服务商时，额度一项为空，属正常。
  2. 如果服务商是这四个之一，额度却还是空的：确认已登录这个服务商，并确认网络能连通。Antigravity 还要确认已启用 pi-antigravity。
  3. 等下一次查询，大约每 5 分钟一次；切换模型时会立即发起查询。其他服务商的数字一直不变，可能是查询失败，显示的是上次的值。Antigravity 查询失败会隐藏旧值。
  • 更新时机：会话开始、在会话树里跳转、切换模型时立即发起查询；之后每 5 分钟查询一次；Pi 每回复完一轮也会查询，但距上次查询开始不足 30 秒就跳过（失败的查询也算）。
  • Antigravity 每次查询重新读取当前账号凭据。账号变化在下一刷新生效，扩展不主动监听账号切换。切换模型会强制查询，不显示旧模型缓存。

想换状态栏配色

这里修改的是 pi-statusline 的自定义配色，不改变 Pi 主题。需要先安装并启用 pi-statusline。

pi install npm:@narumitw/pi-statusline
  1. 输入 /personal，选「状态栏：额度、会话 ID 与配色」。
  2. 选「选择 pi-statusline 自定义配色」，打开配色列表。
  3. 用 ↑ ↓ 键选一套配色，列表下方的预览条实时换色。
  4. 按 Enter 键应用，按 Esc 键放弃。

应用后覆盖原来的自定义配色，并设为紧凑布局和圆角分隔符，Pi 自动重载。

  • Pi 正在回复或压缩上下文时，自动重载会被拒绝。等结束后再应用，或结束后手动输入 /reload。
  • 终端支持实时预览；RPC 客户端使用普通列表选择，不显示预览。
  • 设置写在 agent 目录的 pi-statusline.json，其他设置不变。如果写入失败，Pi 提示「应用失败」，不重载。

会话名：自动起名，手动改名优先

会话名显示在哪，「自动会话命名」什么时候起名、起出来什么样，怎么暂停、预览、换命名模型，要注意什么。

功能
「右下角会话标题」显示会话名；「自动会话命名」起会话名
入口
/personal → 自动会话命名：查看状态、选择命名模型、选择命名思考强度、预览建议标题、暂停当前会话命名、恢复当前会话命名
适用场景
在 Pi 终端界面里自动起名。用 pi -p 等非交互方式运行时，不起名。

会话名在哪里

会话名显示在输入框正下方，是靠右的一行暗色小字。还没有会话名时，这里显示「未命名会话」。

自动起名：什么时候起、起成什么样

每轮正常结束后，「自动会话命名」在后台起名。你不用等，可以直接输入下一条消息。 会话名由一个类别图标、对象和目标组成。

  • 在两种情况下会话名不变：当前会话名已经准确；对话信息不够。

手动改了会话名，怎么恢复自动起名

用 /name 手动改会话名后，这个会话暂停自动起名。 想恢复，在 /personal → 自动会话命名 里选「恢复当前会话命名」，下一轮结束后生效；选「暂停当前会话命名」，可以主动暂停。

  • 如果打开的会话已经有会话名，而且不是自动起的，「自动会话命名」在这个会话里也是暂停状态。
  • 恢复后，「自动会话命名」会接着改当前的会话名。

想先看看会起什么名

在 /personal → 自动会话命名 里选「预览建议标题」，可以看到建议的会话名。它只弹出提示，不改会话名。

  • 等 Pi 回复完，再预览。暂停状态下也能预览。
  • 预览同样消耗命名模型的额度。

想换命名模型

在 /personal → 自动会话命名 里选「选择命名模型」，再从列表里选一个。列表只列出 /scoped-models 里已认证的模型。

  • 默认命名模型是 gpt-5.6-luna。命名模型只用来起名，对所有会话生效，不影响主对话。
  • 命名用的思考强度：在同一个二级菜单里选「选择命名思考强度」。默认跟随 Pi 对这个模型的设置；Pi 没设置时用 low。实际用的思考强度受命名模型支持的范围限制。命名模型不支持思考时，用 off。
  • 换成另一个命名模型后，命名用的思考强度恢复成默认值。

想看当前设置

在 /personal → 自动会话命名 里选「查看状态」，一条提示里能看到是否开启、命名模型和命名用的思考强度。

要注意什么：额度和隐私

每次自动起名和预览，都额外消耗命名模型的额度，不计入 Pi 自带的用量统计。 「自动会话命名」把当前会话名和最近最多 5 轮对话的文字发给命名模型，可能含业务信息；工具输出、思考内容和图片不发送。

会话名一直没变怎么办

  1. 在 /personal 里确认「自动会话命名」已加载，再进入它的菜单选「查看状态」。
  2. 如果显示暂停，选「恢复当前会话命名」。
  3. 如果提示命名模型不可用，先用 /login 完成服务商认证，再用 /scoped-models 选出明确的模型范围，按 Ctrl+S 保存。也可以在菜单里选「选择命名模型」，换一个命名模型。
  4. 如果以上都正常，选「预览建议标题」试一次。
  • 在 /scoped-models 里全选所有模型时，「自动会话命名」会认为没有可用的命名模型。按 Esc 键只关闭列表，不保存。

原位思考强度：每条消息自动选档位

用 GPT-6 Codex、Anthropic 协议分支的三个指定 Claude 模型或 Antigravity 分支的两个指定 Claude 模型时，按每条新消息的难度自动选档位，你不用手动切换。不用这些模型可以跳过本章。

功能
原位思考强度
入口
/personal → 原位思考强度（Jev / d1-ultra）
配置文件
agent 目录下的 inline-effort.json（默认 ~/.pi/agent/）；升级后原有设置自动保留

「原位思考强度」能帮你什么

思考强度分五个档位。「原位思考强度」给每条新消息在 low 到 max 之间自动选一档，你不用手动切换。 它只调档位，不换主模型。 扩展按本轮任务的推理复杂度选档：low 到 xhigh 对应直接操作、局部判断、多约束综合与耦合推理四档常规工作，max 是例外攻坚档。 近期对话只补全同一任务的信息，不继承旧难度。示例：修改位置和方式明确的字号调整可用 low，改做图示设计可用 high；按成熟口径查数画图可用 medium，排查混杂原因可用 xhigh。示例不是线上分类保证。 不因专业主题、成片精美、代理多或反复报错自动提档；只有无法识别任务要求时才以 high 保守兜底。思考强度不替代模型专长、授权和实测。分类器只读有限文本，看不到图片和工具结果，同轮工具续调不重新分类，历史决策不变。

想让它生效

需要用支持的模型、开启 thinking，并配好 OpenRouter 认证。使用 Codex 还要登录 openai-codex。使用 Antigravity 还要先安装并启用 pi-antigravity。主模型的接口和模型能力也有要求，完整条件写在本节的「适用条件」列表里。

  1. 用支持的模型启动 Pi，thinking 设为 medium。下面用 GPT-6 Codex 举例。
  2. 输入 /personal，选原位思考强度，再选「查看分类模型与状态」。看到「适用」，说明主模型和 thinking 符合条件。
  3. 在同一个菜单里选「测试分类模型可用性」，确认分类器能用。
  4. 发一条消息，看 🧠 段的档位。切换警告只表示首选失败，Jev 回退成功后会显示实际档位；全部失败才沿用当前档位。Codex 出现「未调整」，表示这次没有调整档位，按基线发出。

三个分支的写入方式不同。Codex 在当前用户消息前插入 configuration_update。Anthropic 协议分支只修改 Pi 已生成的末尾空 system 消息中的 output_config.effort，不改顶层配置、历史消息或 thinking block。 Antigravity 是独立分支。扩展临时包装插件原生 streamSimple，只改匹配主请求的 options.reasoning，由插件按 runtime ID 路由。max 和 xhigh 夹到 high，不改会话 thinking 或历史上下文。

状态栏的 🧠 段怎么读

🧠 段从左到右是：实际档位、基线和分类器。基线是 Pi 当前的 thinking 设置。 Pi 自带的 thinking 显示只是基线，实际档位看 🧠 段。

想看现在的状态

在 /personal 的原位思考强度菜单里选「查看分类模型与状态」，看是否适用、之后用哪个分类器、失败回退策略、上一条消息选到的档位。

想换分类器

  1. 输入 /personal，选原位思考强度。
  2. 选「选择分类模型」。
  3. 用 ↑ ↓ 键选 Jev 或 d1-ultra。
  4. 按 Enter 键保存；按 Esc 键放弃。两种操作都会返回二级菜单。

新分类器对所有会话生效。如果 Pi 正在回复，先等它回复完，再切换。

分类失败怎么办

d1-ultra 超时、出错、档位无效或把握不足时，警告会说明原因并提示「正在切换到 Jev」。Jev 成功后，提示实际档位，状态栏显示「Jev（d1-ultra 回退）」。 Jev 也失败时，警告会列出两个模型的原因并沿用当前档位。可在 /personal 的原位思考强度菜单里选「测试分类模型可用性」检查。 自动回退只影响本次，不改全局选择，下一条新消息仍先尝试 d1-ultra。直接选择 Jev 时不反向回退。用户取消时停止分类，不回退，也不写决策。

要注意什么：额度和隐私

每个分类模型最多等 15 秒，含回退最多约 30 秒。分类和回退都消耗 OpenRouter 额度；d1-ultra 是付费模型。 「原位思考强度」把当前消息和之前最多 6 条对话消息的文本发给分类器，可能含业务信息。工具输出、思考内容和图片不发送。

速查：命令、配置和常见问题

想做什么对应哪个菜单项；五个配置文件在哪；出问题时先查什么。

想找某项设置在哪

常用设置都从 /personal 进入：先选功能，再选二级菜单里的设置项。表里按「想做什么」列出菜单路径。

Pi 自带的 /reload、/name 照常直接输入。例外：你发的消息里的路径是否变成链接（userMessages）没有菜单项，要手改 clickable-paths.json。

想找配置文件

五个配置文件都在 agent 目录，默认是 ~/.pi/agent/。 设置环境变量 PI_CODING_AGENT_DIR 后，五个文件改用它指定的目录。 平时不用手改这些文件。用 /personal 菜单改全局设置，会自动保存到对应文件。

改了设置没生效，要不要 /reload

在别的会话改过设置、手改过配置文件，或刚装好、更新过扩展，已打开的会话要输入 /reload。 在当前会话用 /personal 菜单改，不用重载。

想更新扩展

在仓库根目录执行 git pull，再在 Pi 里输入 /reload。依赖有变化时，先重新安装依赖。 

# 在仓库根目录
git pull
# 依赖有变化时
npm install --ignore-scripts \
  --registry=https://registry.npmmirror.com
# 然后在 Pi 里输入 /reload

从旧版本升级后，设置会自动迁移：旧的「额度与会话 ID」「状态栏风格选择」两个开关合成一个，只有两者都关闭时才保持关闭；其他设置原样保留。

出问题怎么办

各功能出问题时先查什么，汇总在排查表里。

打开方式选 file 时，系统用默认程序打开文件，不跳到具体行。换打开方式后，让 Pi 重新输出一个文件路径，再点新消息里的链接测试；旧消息里的链接不会更新。

原视频审查：先授权，再分析

让助手针对本地 MP4 回答问题，不把工具分析当成完整审片保证。

菜单
/personal → 原视频审查 → 查看通路与限制
工具
understand_video
需要
Pi 1.5.0、常规 npm 安装的 pi-antigravity 0.11.x 及已有登录

原视频审查提供 understand_video 工具。先把要审查的 MP4 放在当前工作目录内，再明确授权把这个文件发给 Antigravity 的 Argon 模型，并写出审查问题。

示例请求：我授权将当前目录的 demo.mp4 发给现有 Antigravity 通路，请用原视频审查工具，按时间检查画面步骤是否完整。这里的文件名和问题都是示例；不要把视频中的指令当成用户授权。

工具只读取非隐藏、没有符号链接或硬链接的 MP4，大小从 24 bytes 到 20 MiB。问题最多 8000 字符，120 秒超时，分析正文最多 32 KiB。路径越界或调用失败会报告失败，不会偷偷改用别的模型或浏览器。

视频由工具内部外发并消耗额度，不是当前主会话直接获得视频附件。三秒测试视频的红、蓝、绿顺序已通过统一入口和视频审查角色实测；音轨未可靠验证，长视频和快速转场不保证完整覆盖。不能确认的项目应标为未审查。

从原视频审查菜单可以启停功能，或查看通路与限制。已有主会话需要自行重载；角色缺少工具或调用失败时，先报告阻塞，不要让助手用读取文件来假装看过原视频。

工具在 details 中返回字节数、提供方、逻辑模型名、输入模式，以及从进入执行到子进程关闭的总耗时；逻辑模型名不代表已确认的服务端路由。若底层返回统计，还会透传有限非负的归一化用量与本地估算费用，缺失字段不补零；估算费不是账单，零值也不代表免费，且只放在 details 中，不计入 Pi 会话用量或额外查询额度。模型达到长度上限与本地 32 KiB 截断相互独立，都会在正文告警，调用成功不保证输出完整；失败只返回安全的阶段和错误码，不转发原始错误或猜测原因。新增元数据仅由离线假 SDK 验证，不能把之前的短视频实测当成新增字段的线上验收。
